# Security Reports

Do not open a public issue or discussion for a suspected vulnerability, leaked
credential, private transcript or personal-data exposure.

Use this repository's **Security -> Report a vulnerability** private reporting
channel when it is enabled. If that option is unavailable, do not attach the
details publicly: ask the repository owner to provide a private reporting
channel, without including exploit or personal data in the request.

Include affected version, deployment mode, the smallest synthetic reproduction,
impact and redacted diagnostics. Never send your full archive, identity file,
secret configuration, model-provider keys or other people's cards.

Security reports go to the repository owner before triage decisions or public
disclosure. No response deadline or supported-version promise is made by this
pre-release bootstrap. Publication is gated on verifying the private reporting
channel and owner escalation process.
